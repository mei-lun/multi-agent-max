## 当前功能基线

继承 0.1.20 的 Claim、Local Execution Draft、Formal Delivery、多角色 Review Aggregate、实时活动投影和重复启动保护。

- `review_gate` 若存在可返工的上游 `role_task`，必须声明带 `when: changes_requested` 和 `maxTraversals` 的有界回退边，且回退次数不得超过 Review 的 `maxRevisionAttempts`。
- 本地自动协作仅把可执行中状态的 Claim 视为活跃；已提交 Reviewer 的历史 Claim 不再阻塞 `changes_requested` 上游 Task 创建带 lineage 的新 Attempt。
- 生成的标准 Workflow、桌面新建 Workflow 和设计提示词均包含可执行的有界 Review 返工路径。

## 本版本变更记录

### 2026-09-18 - 修复 Review changes_requested 返工停滞

- 类型：修复、工作流校验、测试、文档。
- 用户可见行为：Review 要求修改后，自动协作会继续启动受审上游 Task；已完成 Reviewer 的 Claim 不再让 Run 永久显示为 active。
- 实现范围：Review Gate 工作流编译与导入校验、自动协作规划器、标准/新建 Workflow 生成器、历史 Run Bundle 兼容重建及回归测试。
- 状态与兼容性：版本从 0.1.20 升至 0.1.21；新增仅为新定义的编译/保存约束，不改变已有 Git 事件 Schema。历史冻结 Run 保持可读和可恢复；已有缺少有界返工边的 Workflow 需补充回退边后才能保存新版本或创建新 Run。
- 验证：工作流编译、Workflow package、标准模板、自动协作规划器及真实 Git Attempt 执行测试通过。
- 已知限制：没有上游 `role_task` 的纯 Review Workflow 不生成自动返工边；这类 Workflow 仍需人工决定后续路径。
