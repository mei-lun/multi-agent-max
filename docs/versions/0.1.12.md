## 当前功能基线

本版本继承 `0.1.11` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。角色不共享聊天上下文，正式输入输出通过已校验 Artifact 和 Git commit 交接。
- 角色到角色的文件交接必须经过 Workflow 中显式的 Review 与 `git_merge`。下游 Attempt 按 Git ancestry 固定到已完成集成节点的唯一终端 merge commit，并收到包含 Artifact 类型、路径或 glob、hash、生产节点、Attempt 与来源 commit 的输入清单；未集成或多集成基线歧义时拒绝启动。同一动态节点内无法表达独立 Review/merge 的兄弟 Task 文件 Artifact 交接会在 Task Plan 物化前被拒绝。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 设计助手请求属于当前设计草稿生命周期；切换应用页面时生成继续运行并保留界面状态，只有显式停止或确认放弃当前设计时才取消。重置后的迟到结果不能覆盖新草稿。
- 桌面自动协作由 Renderer 的本机协作协调器按 `automaticWorkflowRunIds` 推进；同一应用进程对相同项目、Run 和 Task 的重叠启动请求会合并，跨 clone 的合法并发 Attempt 继续保留并显示 warning。
- Review 绑定当前选中的不可变已提交 Attempt；过期自动 Review 记为 superseded，不写入 Review 决策、不参与聚合，也不触发 Attempt 失败恢复。
- 当前生产 Attempt 只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP；角色本机绑定、密钥、健康结果和导入事务状态只保存在本机。
- 本地桌面日志、业务诊断和 Pi RPC 日志按记录时间滚动保留 24 小时；日志目录可在设置中修改并于重启后生效。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-17 - 修复设计助手跨页面请求生命周期

- 类型：修复、重构、测试、文档
- 用户可见行为：设计助手生成期间切换到其他页面不会再丢失进行中状态或导致后续发送报错；返回设计页面后仍能看到生成状态和最终结果。用户确认“放弃并新建”时才会取消当前生成并清空草稿。
- 实现范围：将设计助手状态提升到桌面应用根层；为发送和重试增加同步重入保护及结算跟踪；重置草稿时取消活动请求；模型网关在请求前后传播取消；服务端按取消信号和草稿 ID 拒绝迟到结果回写。
- 状态与兼容性：版本从 0.1.11 升至 0.1.12；不新增持久化 Schema、权威事件或 `mam-state` 迁移。设计草稿文件格式保持 `1.0.0`。
- 验证：设计助手服务、恢复、模型网关及相邻 Renderer 组件 5 个测试文件共 33 项通过；lint、TypeScript 类型检查、修改文件格式检查、`git diff --check`、Electron 桌面构建及 Node 24 环境脚本测试通过。Node 24.19.0 下全量 Vitest 为 135 个文件 441 项通过、1 项跳过；剩余 5 项为既有 Windows 基线失败，包括 2 项 POSIX `0o600` 权限断言和 3 项真实 Git merge fixture 断言。
- 已知限制：应用进程退出会随进程终止尚未完成的模型 HTTP 请求；设计请求不跨应用重启恢复。

### 2026-09-17 - 完成任务领取、本地执行草稿与正式交付重构设计

- 类型：文档
- 用户可见行为：无运行时变化。形成了后续实现的最终设计基线：Task 使用可强制接管的排他 Claim；模型超时和本地重试保留在可恢复的本地 Execution Draft；只有校验成功的交付才发布正式 Attempt；下游只读取唯一当前交付；多个开发 Task 和多个审核角色可并行执行，并通过确定性的 Review Aggregate 汇总。
- 实现范围：新增 `docs/superpowers/specs/2026-09-17-claim-local-draft-delivery-design.md` 和 `docs/superpowers/plans/2026-09-17-claim-local-draft-delivery.md`，记录故障复盘、状态与事件模型、Pi 超时和 session 恢复、Claim fencing、Formal Delivery、下游选择、跨角色审核、旧 Run 兼容、权威需求差异、分版本实施任务和验收矩阵。
- 状态与兼容性：不修改运行时代码、持久化 Schema 或现有 `mam-state`。设计明确要求实施前更新现行产品权威中与非排他 Claim、失败 Attempt 历史和恢复语义冲突的条款。
- 验证：人工核对设计与 2026-09-17 的 Pi 超时、Review 聚合失败日志，并与 `final-reuse-integration-plan.md`、`MAM_REQUIREMENTS_DELTA_2026-07-27.md`、当前 Scheduler 协议、Git projection、Attempt 执行和 Review 聚合实现逐项对照；中文规格与实施计划通过占位符、接口一致性、规格覆盖和 `git diff --check` 检查。
- 已知限制：本条仅记录设计，不代表功能已经实现；现有 Run 仍使用旧的非排他 execution notice、预先发布 Attempt 和历史回退选择语义。
