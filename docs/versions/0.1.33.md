## 当前功能基线

继承 0.1.32 仍受支持的角色、工作流、Git 权威状态、Artifact、审核、合并、诊断以及 Pi RPC 的连接故障自动与人工续跑能力。工作流定义仍是带版本的执行图，Run 固定定义版本，任务沿节点固定角色执行。

- 工作流编辑器使用 XYFlow 展示条件、并行分叉、汇合与有界返工。基础 DAG 决定从左到右的阅读顺序，带 `maxTraversals` 的边单独走上方返工通道并显示条件和最大次数。
- 明确可配对的 `parallel`/`join` 显示并行区域；编辑器提供控制流和 Artifact 数据流两种视图。后者只显示静态契约推导的“可能提供”关系，并区分多来源、初始输入和缺少来源，不声称运行时已传输。
- 节点类型通过图标和标签辨认；编辑器可拖动固定节点位置、自动整理、查找节点、查看数据关系详情、选择节点后追踪上游或下游。位置只在可选的 `presentation` 展示字段中保存，不进入执行计划或 Scheduler 语义。
- 无展示元数据的旧 Workflow Definition 仍可打开。Workflow Package 可往返保存新展示字段；只改变展示坐标不改变 `planHash`。含新字段的定义要求同版本应用解析；旧版 strict Schema 不支持读取该字段。

## 本版本变更记录

### 2026-10-29 — 工作流图逻辑与 Artifact 数据关系优化

- 类型：功能、优化、测试、文档。
- 用户可见行为：复杂工作流的并行分叉、汇合和有界返工在编辑器画布中更容易辨认；可切换静态 Artifact 数据关系、固定布局及追踪路径。
- 实现范围：Workflow Definition 展示 Schema 与验证、XYFlow 语义分析/布局/返工边/并行区域/节点和 Inspector、静态 Artifact 关系与定向测试；方案来源为 `docs/superpowers/specs/2026-10-29-workflow-diagram-logic-and-dataflow-design.md`。
- 状态与兼容性：从 0.1.32 升至 0.1.33；新增可选 `presentation` 字段，旧定义不需迁移；`planHash` 和调度语义不变。新字段会改变 Definition/Bundle 内容 Hash，旧版应用的 strict Schema 无法解析新定义，需要同版本应用参与。
- 验证：定向 Vitest 8 个文件、31 项通过；TypeScript、oxlint、核心与桌面生产构建通过；seeded desktop smoke 通过。全仓 Vitest 首轮为 168 个文件通过、4 个文件失败（562 项通过、6 项失败、1 项跳过），其中 1 项新界面中英混用的覆盖测试已修复并定向重跑通过；其余 5 项为 Windows 文件权限及 Git 合并测试失败，与 0.1.32 已知限制一致。`git diff --check` 通过。
- 已知限制：Artifact 数据流视图只展示定义时可能的数据关系；定义编辑器没有 Run 初始输入与完整运行时 ArtifactVersion lineage，因此未匹配输入标为“待核对初始输入”，不声称缺失或已传输。无明确配对的并行结构不绘制闭合区域；密集图的无交叉正交布线和 macOS 实机视觉验收仍需后续验证。
