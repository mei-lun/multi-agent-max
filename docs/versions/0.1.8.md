## 当前功能基线

本版本继承 `0.1.7` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 仅在请求未失败且已停止处理后收集结果；请求超时、重试耗尽及中止均保留执行失败原因，内部重试成功可正常完成。压缩 RPC 诊断保留脱敏后的失败原因，不保存重复正文。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Pi 的 OpenAI Responses / Chat Completions 自定义根地址默认补 `/v1`，与设计助手一致；完整操作地址去除 SDK 会追加的操作后缀，已有版本或自定义路径前缀保留。
- Pi 的 OpenAI Responses / Chat Completions 请求使用 `Multi-Agent-Max` User-Agent，明确标识宿主应用，兼容拒绝通用 SDK 默认标识的中转站。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- 设置页支持删除执行器、提供方和模型的活动配置；活动角色、模型及当前项目未结束运行引用中的配置必须先解除引用。删除保留历史版本、运行数据、本机凭据和绑定；内置 Pi 删除后不会在重启时重新注册。
- 本地桌面日志、业务诊断和 Pi RPC 日志按记录时间滚动保留 24 小时，启动及每分钟清理；取消 5 MB 轮转和 3000 条提前截断。日志记录应用版本、前端错误、IPC 请求关联、错误堆栈与 cause、执行模型及工作目录、后台自动启动失败。详见[开发日志说明](../readme/MAM_LOGGING.md)。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。
