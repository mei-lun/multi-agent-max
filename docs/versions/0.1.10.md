## 当前功能基线

本版本继承 `0.1.9` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。任何候选事件 batch 在写入 Run Bundle、Effective Config、Artifact、事件文件或 Git commit 前，必须与当前事件历史完成一次可重建性校验。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 桌面自动协作只由 Renderer 的本机协作协调器按 `automaticWorkflowRunIds` 推进；主进程不再独立扫描并启动 Task。同一应用进程对相同项目、Run 和 Task 的重叠启动请求会合并，跨 clone 的合法并发 Attempt 继续保留并显示 warning。
- Review 绑定当前选中的不可变已提交 Attempt；目标 Task 离开 `in_review` 或选中结果已改变后到达的自动 Review 记为 `automatic_review_superseded`，不写入 Review 决策、不参与聚合，也不触发 Attempt 失败恢复。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 仅在请求未失败且已停止处理后收集结果；请求超时、重试耗尽及中止均保留执行失败原因，内部重试成功可正常完成。压缩 RPC 诊断保留脱敏后的失败原因，不保存重复正文。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Pi 的 OpenAI Responses / Chat Completions 自定义根地址默认补 `/v1`，与设计助手一致；完整操作地址去除 SDK 会追加的操作后缀，已有版本或自定义路径前缀保留。
- Pi 的 OpenAI Responses / Chat Completions 请求使用 `Multi-Agent-Max` User-Agent，明确标识宿主应用，兼容拒绝通用 SDK 默认标识的中转站。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- 设置页支持删除执行器、提供方和模型的活动配置；活动角色、模型及当前项目未结束运行引用中的配置必须先解除引用。删除保留历史版本、运行数据、本机凭据和绑定；内置 Pi 删除后不会在重启时重新注册。
- 本地桌面日志、业务诊断和 Pi RPC 日志按记录时间滚动保留 24 小时，启动及每分钟清理；日志记录应用版本、前端错误、IPC 请求关联、错误堆栈与 cause、执行模型及工作目录、过期自动 Review。详见[开发日志说明](../readme/MAM_LOGGING.md)。
- 设置 -> 本机绑定支持查看和修改日志目录，默认展示当前绝对路径；保存后重启生效，三类日志统一写入该目录，旧目录继续执行 24 小时清理，旧文件不搬迁。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-15 - 修复线性工作流中的重复 Attempt 与过期 Review

- 类型：修复、重构、测试、文档
- 用户可见行为：启用本机自动协作后，每个线性 Task 只由 Renderer 协调器推进；同一应用内重叠的自动或手动启动请求不会再为同一 Task 创建第二个 Attempt。合法跨 clone 并发仍保留。并发执行造成的迟到自动 Review 被标记为 superseded，不再中断执行或让 Run 进入 `stale_review_attempt` 状态错误。
- 实现范围：删除未读取本机自动协作设置的主进程 `MamAutomaticWorkflowRunner` 及桌面 wiring；`MamAttemptExecutionService` 与 `LocalTaskExecutionRegistry` 增加项目、Run、Task 维度的进程内 single-flight 启动合并；自动 Review 发布前及发布异常后重验 Review Gate 与冻结 subject，提交或聚合竞态中的过期结果转为 superseded 诊断，已完成的同 Gate 聚合保持 submitted；Review reducer 使用 `in_review` 与 `selectedAttemptId` 判断当前 subject；聚合完成、人工分歧解决及后提交的并发结果清除旧 Panel 活动指针，后者同时使旧决策失效；人工批准分歧后继续推进下一道 Review Gate；Git 状态仓库在任何持久化前 replay 当前事件与候选 batch。
- 状态与兼容性：版本从 0.1.9 升至 0.1.10；不新增或修改事件 Schema，不迁移或修复旧 Run 数据。已有合法 Run 可继续重建；开发阶段已含非法事件的旧 Run 仍需放弃或单独清理。跨 clone 并发 Attempt 与 `concurrent_execution_warning` 语义保持不变。
- 验证：Node 24.19.0 下 7 个专项文件 41 项测试通过，覆盖同一进程重复启动 single-flight、迟到及抛错/正常返回的聚合窗口内自动 Review superseded、连续 Review Gate 共用 subject、人工批准分歧后推进下一道 Review Gate、选中已提交 subject 在另一并发 Attempt 运行时仍可审核、并发结果替换后旧 Panel/Review 退休、语义非法 batch 不改变 Git HEAD、事件、summary 或 Effective Config，以及既有跨 clone 并发 warning。排除 3 个既有 Windows 基线失败文件后，全仓 133 个测试文件、422 项通过、1 项跳过；Node 脚本测试 9 项通过、2 项跳过。全仓 lint、Node 24 typecheck、核心构建与 Electron 桌面构建通过；本次修改的 20 个受格式规则约束文件通过 oxfmt，完整 format:check 仍受仓库既有 CRLF 基线限制。完整 Vitest 另有 5 项既有 Windows 失败：2 项 POSIX `0o600` 权限断言及 3 项真实 Git merge fixture 断言；后 3 项在 Node 20 下同样复现。`verify:final` 在 Windows 上因脚本 `spawnSync pnpm.cmd EINVAL` 无法运行冻结的 macOS 验收命令，生成报告已恢复，未更新正式验收证据。
- 已知限制：进程内启动合并不跨应用实例；跨 clone 仍可能完成已过期工作，但其自动 Review 决定会被安全忽略。无旧数据迁移或修复工具。
