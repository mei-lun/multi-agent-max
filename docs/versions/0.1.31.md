## 当前功能基线

继承 0.1.30 的 Review 建议化、同 Draft timeout retry 和手动 Continue，并修正自动 Review 交付与进程重启恢复之间的不一致。

- 只有 `blocker` finding 或模型 `blocked` 是致命审核结果；`high`、`medium`、`low` findings 在 `approved` Decision 中保留为下版本建议，不创建返工 Attempt。
- 自动 Review 的非致命 `changes_requested` 归一为 `approved`；致命结果仍进入已有的有界返工或阻塞流程。
- 应用启动或项目重新挂载时，自动工作流会扫描本机仍持有有效 claim 的可恢复 Draft。Review Draft 若已经保存模型 final answer，会直接复用结果完成提交，不再次调用模型。
- `executor_timeout` 在同一 Attempt、Draft、worktree 和 Pi session 内自动续跑；continuation 次数跨重启持久化，且所有续跑共享该 Attempt 的累计运行时预算。
- 自动续跑达到角色 retry budget 后保留 `waiting_for_resume`；用户可从 Attempt 页面手动 Continue，同样复用原 Draft。
