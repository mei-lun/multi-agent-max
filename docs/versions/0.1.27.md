## 当前功能基线

继承 0.1.26 的 Provider 地址归一化、Responses 流式传输、响应头超时边界、推理强度配置、Design Assistant 单次模型调用、本地响应归一化及静态 Workflow 检查。

- Pi RPC 保留结构化事件中的响应阶段；`commentary` 继续用于活动展示和诊断，只有 `final_answer` 进入业务交付物与可选标准 Attempt Result 解析。
- Review Role 的最终报告可使用 JSON、Markdown 或含明确结论的自然语言；MAM 在 Artifact 严格校验前复用现有 Review 归一化器，生成内部标准 Review JSON。
- 非 Review 的显式 `json-schema` Artifact 继续严格校验；本次修改不恢复终端尾部、进程退出、自然语言自称完成或 idle 即完成语义。
- 已完成模型生成但在本地 Review 解析阶段失败的 Pi Local Execution Draft，可从保留 session 的明确 `final_answer` 本地恢复，不再次调用模型，并保留原 Attempt、Executor invocation、冻结配置和 worktree。
- 多个无阶段文本块不会被猜测合并为交付；缺少、歧义或无可靠 Review 结论时继续保留 Draft 并进入明确错误状态。
- 修复设计与验证范围记录在 [`2026-09-20-flexible-review-output-recovery-design.md`](../superpowers/specs/2026-09-20-flexible-review-output-recovery-design.md)。

## 本版本变更记录

### 2026-09-20 - 恢复格式中立的 Role 交付并补齐 Review 输出边界

- 类型：修复、重构、测试、文档。
- 用户可见行为：Review Role 可以使用 JSON、Markdown 或清晰自然语言提交审核报告；OpenAI Responses 同一消息中的进度说明不再污染最终交付物。已生成完整审核结果但本地解析失败的保留 Draft 可在用户确认恢复后直接完成本地校验，不产生新的 Provider 请求或费用。
- 实现范围：新增 Pi assistant response 阶段选择器；Pi Adapter 只向结果收集器交付 `final_answer`；Review 归一化提前到内部 JSON Artifact 校验之前；Review Prompt 改为格式中立；Local Execution Draft 恢复复用持久化 Pi session；补充 selector、collector、runner、Draft 恢复和真实 Git 执行测试。
- 状态与兼容性：版本从 0.1.26 升至 0.1.27；不修改 Workflow、Review、Attempt、Artifact 或 Git 事件 Schema，无共享状态迁移。Local Execution Draft Schema 未变化；恢复信息只在进程内 Prepared Attempt 中派生。旧 Provider 的单文本响应继续兼容。
- 验证：Node 24.19.0 下 12 个定向文件 56 项测试通过，其中包含真实 Git 状态上的 Service 重启与同 Attempt 无模型 Review 恢复，以及成功/中止响应、最新 turn、等待恢复和普通非 Review 续跑边界；既有真实 Git Attempt 执行套件 10 项通过；全仓 lint、TypeScript 类型检查、核心构建、Electron 桌面构建和 Node 脚本测试通过。限制 Vitest 文件并发后的全仓测试有 156 个文件、508 项通过、1 项跳过，7 项既有或并行开发中的 Windows/fixture 失败；完整格式检查仍受 395 个既有文件的格式基线阻塞。
- 已知限制：无模型恢复要求保留的 Pi session 中存在一个明确 `final_answer`，或旧 Provider 只有一个无阶段文本响应；多个无阶段文本候选不会自动选择。格式中立归一化仅适用于 Review，其他显式 JSON Artifact 仍要求合法 JSON。全仓剩余失败包括 Windows `0o600` 权限断言、三个 merge/revision fixture 和当前未提交的 reasoning UI 中文覆盖；均不在本次 Review 输出链范围内。
