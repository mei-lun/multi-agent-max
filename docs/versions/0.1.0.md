## 当前功能基线

### 1. 产品边界与运行架构

- MAM 是本地 Electron 多 Agent 工作流控制平面，以工作流图和确定性 Scheduler Kernel 推进状态，不把模型输出直接当作权威状态。
- Git 是共享状态权威：冻结的 Run Bundle、Task、Attempt、Artifact、Review、Approval 和 Merge 证据以 append-only 事件保存在独立 `mam-state` 分支，可确定性 replay。
- 当前正式执行路径只启用 Pi RPC。Codex CLI 和 Grok CLI Adapter 及测试仍保留，但尚未接入当前发布路径，也不存在 Executor、Provider 或 Model 静默 fallback。
- 首发门禁是 macOS；边界代码保持路径可移植，Windows 打包脚本仅为后续工作预留。

### 2. 带版本的角色、资源与本机配置

- 用户可创建带版本的 Role Profile，组合 Executor、Provider、Model、系统 Prompt、Skill、MCP Server、知识库、工具、权限、预算、重试和上下文策略。
- Provider、Model、Executor、Skill、MCP 和 Knowledge Base Profile 具有版本和兼容性校验；Run Bundle 冻结角色内容及 Hash，其他 clone 不依赖创建者的本机 Catalog 也能继续运行。
- 可执行文件路径、凭证、MCP 连接、Skill/知识库绑定等机器相关信息保存在 Electron user-data，不写入共享 Git 状态。
- 本机密钥支持加密存储或由绑定 ID 映射的环境变量；Effective Config 只记录引用和内容 Hash，不记录明文。
- 角色页和“我的角色”支持按工作流筛选，只显示与所选工作流固定角色有关的内容；删除/停用角色或 Profile 时执行引用保护。

### 3. Design Assistant

- 使用已有 Model Profile 在本机进行多轮需求澄清、方案比较和头脑风暴，不自动读取项目文件。
- 设计产物支持按部分检查和确认，只有用户明确应用后才创建新角色与工作流，或生成现有工作流的新版本。
- 草稿保存在本机；应用设计不会启动 Run 或创建 Task。
- 生成结果经过规范化、身份校验、Schema 校验和 Workflow Compiler 校验；模型返回不完整时保留可恢复草稿和诊断，而不是隐式应用错误方案。

### 4. 工作流设计与管理

- 可视化编辑带版本的 Workflow Definition，支持 `role_task`、`dynamic_tasks`、`review_gate`、`approval_gate`、`human_review_gate`、`condition`、`parallel`、`join`、`artifact_transform`、`command`、`git_merge` 和 `finish`。
- 每个可执行角色节点在设计时固定且只固定一个角色，Run 中不能改派；系统节点和人工节点不绑定角色。
- 节点 Inspector 可配置输入/输出 Artifact 契约、审核数量、预算、运行时间、循环上限和类型专属字段；保存时执行 Schema、编译、环检测和有界返工校验。
- 条件分支会取消未选择路径并按选中路径汇合；系统节点产物和失败命令证据可从 Git 状态 replay。
- 支持工作流包导入、导出和带引用检查的删除；同一工作流可持续创建新版本并从指定版本启动 Run。

### 5. 默认自动执行与有界返工

- Run 启动或状态变化后，自动运行器按稳定顺序扫描可执行 Task。依赖已满足、没有活动 Attempt 且恰好绑定一个固定角色的普通 Task、动态 Task 和 Review Task 会被自动分配并启动。
- 普通 Agent `review_gate` 产出结构化 `approved`、`changes_requested` 或 `blocked`。`approved` 自动解锁工作流下游。
- `changes_requested` 会把可执行状态交回工作流编译后确定的受审产出 Task；系统自动为固定原角色创建新 Attempt，记录 `previousAttemptId`，以先前提交为返工基线，完成后再次生成 Review Task。
- 多级审核始终复审原始产出节点的最新不可变 Attempt/Artifact/commit，不会误审上一个审核节点的报告。
- 返工受 `maxRevisionAttempts` 或回退边 `maxTraversals` 约束；达到上限归一化为 `blocked`，禁止无界循环。
- 普通自动链路不需要用户点选下一节点、重新指派角色或手动再次提交审核。只有显式 `approval_gate`/`human_review_gate`、角色澄清、无法自动解决的 Reviewer 分歧、`blocked`、`reconciliation`、资源缺失或 preflight 失败会暂停等待人工处理。

### 6. Agent 审核、人工审核与意见聚合

- Agent Review 绑定精确的 Attempt、结果 Hash、Artifact Hash 和可选 commit，自动创建审核面板和固定角色 Review Task。
- Reviewer 结果经过结构化契约解析；`changes_requested` 必须包含可执行问题，多个 Reviewer 按确定性 quorum 聚合，意见分歧进入人工决议门禁。
- `human_review_gate` 审核最新不可变产物。用户选择通过、要求修改或阻塞；修改和阻塞都要求填写意见。
- 人工要求修改时，系统按 `revisionTargetNodeId` 把意见交给固定上游产出角色。角色先完成返工沟通，用户确认理解后才创建带 lineage 的新 Attempt；修改后回到同一人工门禁。
- 旧 Attempt 的审核决定不能放行新 Attempt，审核通过后只有验证证据仍然有效且工作流包含 Git 合并阶段时才发布合并就绪状态。

### 7. 角色澄清与“待我处理”

- 每个角色 Task 都可原生请求人工输入。角色仅在不确定性会实质改变结果且无法从上下文查明时暂停当前 Task 和依赖下游，独立并行分支继续执行。
- 单批最多五个独立问题；决策问题提供 2–3 个有实质差异的方案、取舍、唯一推荐和理由，事实问题接受自由文本。
- 用户可以逐项或批量回答、采用推荐方案或补充自由文本。角色必须提交理解摘要；用户可以确认，也可以要求继续澄清。确认前不得开始或恢复实际修改。
- 问题、回答、摘要、修订、确认和人工审核决定全部写入 append-only Git 事件，并绑定当前 Workflow Run、Task、Attempt 和 actor authority。
- “待我处理”统一展示角色问题、返工沟通和人工审核，按影响范围、阻塞 Task 数、创建时间和稳定 ID 确定性排序，并通过独立 Dialog 进行多轮处理。

### 8. Attempt、Artifact、Git 与恢复

- 代码 Attempt 使用独立分支和 worktree，冻结 Effective Config，生成结构化结果、不可变 Artifact、验证证据、Git Diff 和完整 lineage。
- 首次执行空仓库时，仅在 worktree 干净的前提下创建空初始 commit；不会隐式提交 staged、modified 或 untracked 用户文件。
- Preflight 在权威状态变更前检查 Executor 和资源；失败时 Task 保持可重试。Artifact 内容和 Hash 在 Kernel 接受结果前校验。
- 中断或未知副作用进入 reconciliation/recovery 流程；恢复 Attempt 复用唯一恢复计划和 `previousAttemptId`，并保留旧 Attempt 历史。
- Execution Notice 是非排他提示而不是锁；多个 clone 并发执行同一 Task 时保留全部 Attempt，并在 UI 暴露冲突状态。

### 9. 合并、冲突与交付

- 审核通过的不可变 revision 进入稳定排序的 Merge Queue；执行时在隔离 integration worktree 中重新验证、合并并按策略推送目标分支。
- 合并就绪绑定精确审核结果、commit 和验证策略，过期证据不会被复用。
- 合并冲突会创建固定协调角色的可分配 Task；其结构化结果必须产生经过校验的双父提交，并记录冲突解决 lineage。
- `git_merge` 节点只根据持久化的合并证据完成，随后才允许 Workflow Run 到达 `completed`。

### 10. 桌面界面、观测与诊断

- 桌面侧边栏包含概览、设计助手、角色、工作流、运行记录、实时观测、我的角色、待我处理、审核、合并队列、资源和设置。
- Runs 展示 Task、Attempt 时间线、结果、Artifact、Git Diff、恢复、审批和集成状态；历史 Attempt 不被覆盖。
- Live Activity 按节点汇总角色消息、工具调用、命令、Token 用量和状态变化，可筛选活动/待处理节点并导出关联活动记录。
- 诊断日志和导出记录关联 ID、执行事件与失败信息，同时避免持久化明文密钥。
- Renderer 通过 sandboxed preload 的窄 IPC API 访问主进程；界面支持简体中文与英文，并遵循 `docs/STYLEGUIDE.md` 的 Token 和 shadcn 组件约束。

## 当前需要人工介入的边界

以下情况是设计上的暂停点，不属于自动流转失败：

1. 工作流显式配置 `approval_gate` 或 `human_review_gate`。
2. 角色发起澄清，等待用户回答并确认最终理解。
3. 多 Reviewer 聚合出现无法自动解决的意见分歧。
4. Review 或返工达到上限后进入 `blocked`。
5. Attempt 存在未知副作用，需要 `reconciliation` 或恢复计划。
6. Executor、Provider、Model、Skill、MCP、知识库或本机绑定缺失，或 preflight 失败。
7. Merge Queue 出现需要协调角色处理的合并冲突。

## 已知限制与后置范围

- 当前只以 Pi RPC 作为生产 Executor；Codex CLI 与 Grok CLI 尚未启用。
- macOS 是当前发布门禁；Windows 和 Linux 还不是正式支持目标。
- 不包含 Device Registry、设备分配、排他 Lease、SSH/WSL 主机编排、容器、jcode、独立 Agent Session、Role 继承、Session Override、自动 fallback、Terminal Tail 完成语义或 Hosted Issue/PR 集成。
- 本档案不是测试通过声明。代码继续变化后，应重新执行与改动风险匹配的验证，并把结果追加到下方记录。
