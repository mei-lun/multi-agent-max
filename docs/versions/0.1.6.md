## 当前功能基线

本版本继承 `0.1.5` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 仅在请求未失败且已停止处理后收集结果；请求超时、重试耗尽及中止均保留执行失败原因，内部重试成功可正常完成。压缩 RPC 诊断保留脱敏后的失败原因，不保存重复正文。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Pi 的 OpenAI Responses / Chat Completions 自定义根地址默认补 `/v1`，与设计助手一致；完整操作地址去除 SDK 会追加的操作后缀，已有版本或自定义路径前缀保留。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- 设置页支持删除执行器、提供方和模型的活动配置；活动角色、模型及当前项目未结束运行引用中的配置必须先解除引用。删除保留历史版本、运行数据、本机凭据和绑定；内置 Pi 删除后不会在重启时重新注册。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-14 — 修复角色执行的 OpenAI API 地址

- 类型：修复、测试
- 用户可见行为：只填中转站域名时，角色调用与设计助手使用相同的 `/v1` API 前缀，避免 Pi 向缺少版本的地址发送请求；完整操作地址不会被重复追加后缀。
- 实现范围：Pi `models.json` 地址物化、地址回归测试及真实 Pi 子进程本地服务测试；不改变模型、提供方、鉴权或自动回退策略。
- 状态与兼容性：版本从 0.1.5 升至 0.1.6；无 Schema 或 Git 事件迁移，不改写已保存 Profile、密钥或历史 invocation；新生成的 invocation 使用修正后的地址。其他协议保持原行为。
- 验证：使用 Node 24.19.0。修复前，真实 Pi 本地服务测试中裸域名和完整操作地址均复现 HTTP 403，`/v1` 通过；修复后，Responses / Chat Completions 的根地址、`/v1`、完整操作地址共 6 组真实进程测试通过，服务端严格验证请求路径和 Bearer 鉴权，并完成工具调用与结果提交。地址单测及设计助手回归共 24 项通过。改动文件格式检查、全仓 lint、typecheck、核心和桌面构建通过；独立审查无待修问题。另跑原有 Pi Adapter 测试 9/10 通过，一项在 Windows 环境收到空 stderr，未满足原有 `[REDACTED]` 断言；未声称全部测试通过，未运行全仓测试。终端默认 Node 20.19.6 低于项目最低要求，无法加载当前 Pi 依赖。
- 已知限制：未使用真实中转站密钥验证远端请求；修复路径不代表排除了远端权限或策略导致的其他 403。macOS 发布验证仍需单独完成。
