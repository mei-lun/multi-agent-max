## 当前功能基线

继承 0.1.25 的 Provider 地址归一化、Responses 流式传输、响应头超时边界、推理强度配置、协议分流和 Design Assistant 诊断。

- 每条 Design Assistant 消息只发起一次模型请求；静态工作流问题由 MAM 本地校验，不自动触发模型修复请求。
- MAM 本地归一化 Review 节点缺失的标准边界值，并按正式 Schema 移除模型响应中的未知字段。
- 候选工作流存在静态问题时仍保存助手回复和草稿，但继续阻止用户确认无效方案。
- 故障原因、修复过程和防回归检查记录在 [`设计助手不可用故障复盘-2026-09-20.md`](../readme/设计助手不可用故障复盘-2026-09-20.md)。

## 本版本变更记录

### 2026-09-20 - 修复 Design 响应契约并移除自动模型修复

- 类型：修复、优化、测试。
- 用户可见行为：Design Assistant 不再因 `minimumDecisions`、`maxRevisionAttempts` 或其他 Schema 已明确排除的额外字段连续调用模型三次；一次响应即可进入本地草稿和静态检查流程。
- 实现范围：Design 响应归一化、Proposal Generator 单次调用语义、Design Assistant 静态问题持久化、产品权威文档及回归测试。
- 状态与兼容性：版本从 0.1.25 升至 0.1.26；无持久化 Schema、Profile 或草稿迁移变化。
- 验证：响应归一化、恢复、Service、Gateway、Provider 和 Pi 定向测试，TypeScript 类型检查、lint、格式检查和桌面构建。
- 已知限制：无法解析为 Design 响应基本结构的模型输出仍会失败，但不会自动产生额外模型请求。

### 2026-09-20 - 记录 Design Assistant 不可用故障复盘

- 类型：文档。
- 用户可见行为：无运行时变化；新增可追溯的故障时间线、日志证据、根因、修复方法和排障检查清单。
- 实现范围：新增 Design Assistant 中文故障复盘，并从当前版本档案建立索引。
- 状态与兼容性：无 Schema、Profile、草稿、运行时或迁移变化；版本继续使用 0.1.26。
- 验证：对照 Git 提交 `3542eba`、版本档案、脱敏 runtime 日志和最终真实端到端验证结果逐项核对。
- 已知限制：Provider 后台明细不进入仓库；文档只记录经过客户端日志和用户提供记录交叉确认的数据。
