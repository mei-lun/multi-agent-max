## 当前功能基线

继承 0.1.21 的 Claim、Local Execution Draft、Formal Delivery、多角色 Review Aggregate、实时活动投影、重复启动保护和有界 Review 返工。

- `review_gate` 若存在可返工的上游 `role_task`，必须声明带 `when: changes_requested` 和 `maxTraversals` 的有界回退边，且回退次数不得超过 Review 的 `maxRevisionAttempts`。
- 本地自动协作仅把可执行中状态的 Claim 视为活跃；已提交 Reviewer 的历史 Claim 不再阻塞 `changes_requested` 上游 Task 创建带 lineage 的新 Attempt。
- 生成的标准 Workflow、桌面新建 Workflow 和设计提示词均包含可执行的有界 Review 返工路径。
- Design Assistant 的直接模型请求在本机 runtime 日志中记录脱敏的 endpoint、协议、Profile 版本、请求体大小、HTTP 响应元数据、耗时和失败阶段。

## 本版本变更记录

### 2026-09-20 - 增加 Design 模型请求链路诊断

- 类型：优化、诊断、测试、文档。
- 用户可见行为：Design Assistant 请求失败后，可从 `runtime.jsonl` 判断实际 endpoint 和协议，并区分等待响应头与读取响应体阶段；模型请求行为本身不变。
- 实现范围：Design 模型网关生命周期诊断、桌面 runtime logger 接入及网关回归测试。
- 状态与兼容性：版本从 0.1.21 升至 0.1.22；不改变 Git 事件、Profile 或 Draft Schema，无迁移要求。诊断不记录 API Key、Authorization、prompt、请求体或响应正文。
- 验证：Design 模型网关与 runtime logger 共 27 项测试、TypeScript 类型检查、lint、改动文件格式检查和桌面生产构建通过；全仓格式检查因 406 个既有文件不符合当前 oxfmt 而未通过。
- 已知限制：日志只能确认客户端 endpoint 和 HTTP 生命周期；请求在远端代理内部的路由仍需结合 Provider 的 request ID 和服务端日志排查。当前仓库仍有本次改动以外的全仓格式基线问题。
