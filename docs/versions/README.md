# 版本记录规则

版本档案用于同时回答两件事：当前版本到底支持什么，以及每次改动为什么发生、改到了哪里、如何验证。它是面向维护者和 AI 的功能记忆，不替代产品权威文档或 Git 历史。

软件版本以根目录 `package.json` 的 `version` 为准。

## 强制更新规则

每一组有意的功能、优化、缺陷修复、重构、文档或配置改动，都必须在同一变更集中更新当前版本档案。完成改动前必须：

1. 先阅读 `AGENTS.md`、本规则和当前版本档案。
2. 更新“当前功能基线”：新增、删除或改变行为时，必须同步修正对应条目，不能只在末尾追加一句变更日志。
3. 在“本版本变更记录”末尾追加日期条目，不改写或删除已经发生的历史。
4. 每个条目至少记录用户可见行为、实现或文档范围、状态/Schema/迁移影响、验证证据和已知限制；没有影响时明确写“无”。
5. 新增版本号时创建 `docs/versions/<version>.md`，继承仍然有效的功能基线，并更新本索引。旧版本档案冻结保存。

若一个提交只更新自动生成的验收证据，可以与触发它的功能改动记录在同一条；除此之外，不得以“改动很小”为由跳过版本记录。

## 变更条目模板

```markdown
### YYYY-MM-DD — 简短标题

- 类型：功能 / 优化 / 修复 / 重构 / 文档 / 配置
- 用户可见行为：发生了什么变化。
- 实现范围：关键模块或文档路径。
- 状态与兼容性：事件、Schema、迁移、兼容性影响；没有则写“无”。
- 验证：执行的命令、测试或人工核对。
- 已知限制：尚未覆盖的范围；没有则写“无”。
```
