## 当前功能基线

本版本继承 `0.1.6` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 仅在请求未失败且已停止处理后收集结果；请求超时、重试耗尽及中止均保留执行失败原因，内部重试成功可正常完成。压缩 RPC 诊断保留脱敏后的失败原因，不保存重复正文。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Pi 的 OpenAI Responses / Chat Completions 自定义根地址默认补 `/v1`，与设计助手一致；完整操作地址去除 SDK 会追加的操作后缀，已有版本或自定义路径前缀保留。
- Pi 的 OpenAI Responses / Chat Completions 请求使用 `Multi-Agent-Max` User-Agent，明确标识宿主应用，兼容拒绝通用 SDK 默认标识的中转站。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- 设置页支持删除执行器、提供方和模型的活动配置；活动角色、模型及当前项目未结束运行引用中的配置必须先解除引用。删除保留历史版本、运行数据、本机凭据和绑定；内置 Pi 删除后不会在重启时重新注册。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-14 — 修复中转站对 Pi SDK 客户端标识的拦截

- 类型：修复、测试
- 用户可见行为：角色请求使用应用自身 User-Agent，解决 API 地址正确时仍因默认 SDK 标识被中转站拒绝的 403。
- 实现范围：Pi OpenAI 协议的 `models.json` 请求头物化及真实进程回归；通过 Pi 原生 headers 配置传递，不修改第三方依赖。
- 状态与兼容性：版本从 0.1.6 升至 0.1.7；无 Schema 或 Git 事件迁移，不改写已有 Profile、历史 invocation 或凭据。新 invocation 使用应用标识；其他协议不变，不切换模型、提供方或鉴权。
- 验证：无凭据和无效凭据的远端对照请求均证实：相同请求的默认 OpenAI SDK User-Agent 返回纯文本 403，应用 User-Agent 返回 API JSON 鉴权错误 401。使用本机已保存凭据，通过与 Pi 相同版本 SDK 向相同中转站和模型发出最小流式请求，返回 HTTP 200 和 `response.completed`，凭据未输出或写入诊断文件。另使用当前 `piModels` 生成配置，在隔离临时目录启动已安装 Pi CLI，通过同一真实中转站及模型正常返回 `OK`，`stopReason=stop`、进程退出码 0；未执行原工作流或项目工具，临时配置已清理。真实 Pi 回归在未修复时 3 个 Responses 场景复现 403；修复后，严格校验 User-Agent、路径和鉴权的 6 组真实进程用例，以及地址与设计助手回归共 30 项全部通过。Node 24.19.0 下改动文件格式检查、全仓 lint、typecheck、核心和桌面构建通过；独立审查无待修问题。未运行全仓测试。
- 已知限制：不同中转站策略可能不同，应用标识不保证消除所有远端 403。macOS 发布验证仍需单独完成。
