## 当前功能基线

继承 0.1.22 的 Claim、Local Execution Draft、Formal Delivery、多角色 Review Aggregate、实时活动投影、重复启动保护、有界 Review 返工和脱敏的 Design Assistant 模型请求诊断。

- `review_gate` 若存在可返工的上游 `role_task`，必须声明带 `when: changes_requested` 和 `maxTraversals` 的有界回退边，且回退次数不得超过 Review 的 `maxRevisionAttempts`。
- 本地自动协作仅把可执行中状态的 Claim 视为活跃；已提交 Reviewer 的历史 Claim 不再阻塞 `changes_requested` 上游 Task 创建带 lineage 的新 Attempt。
- 生成的标准 Workflow、桌面新建 Workflow 和设计提示词均包含可执行的有界 Review 返工路径。
- Design Assistant 的直接模型请求在本机 runtime 日志中记录脱敏的 endpoint、协议、Profile 版本、请求体大小、HTTP 响应元数据、耗时和失败阶段。
- OpenAI Responses 与 OpenAI Compatible Provider 使用同一规范化后的 Provider 根地址发现模型，并始终按选定协议请求 `/responses` 或 `/chat/completions`。

## 本版本变更记录

### 2026-09-20 - 修复 OpenAI 中转地址与模型发现兼容性

- 类型：修复、优化、测试、配置。
- 用户可见行为：填写带 `/responses`、`/chat/completions` 或 `/models` 结尾的 OpenAI 中转地址时，模型目录仍从正确的 `/models` 获取；Design Assistant 与 Pi RPC 按用户选择的协议调用正确的消息端点。模型发现超时窗口从 12 秒提高到 30 秒，以适配冷启动中转。
- 实现范围：新增共享的 OpenAI Provider 地址归一化模块，接入模型目录、连接保存、Design Assistant 与 Pi RPC 启动配置；回归测试覆盖交叉协议操作地址。
- 状态与兼容性：版本从 0.1.22 升至 0.1.23；旧 Provider Profile 在读取和执行时同样会被规范化，新连接保存为根地址。未改变 Git 事件、Profile Schema 或迁移要求。
- 验证：Provider model catalog、Design model gateway、Pi launch configuration 和 Profile command 定向测试，TypeScript 类型检查及改动文件格式检查。
- 已知限制：中转服务必须实际实现所选协议的消息端点和对应的响应格式；本修复不提供协议自动 fallback。
