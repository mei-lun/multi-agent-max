## 当前功能基线

本版本继承 `0.1.3` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 仅在请求未失败且已停止处理后收集结果；请求超时、重试耗尽及中止均保留执行失败原因，内部重试成功可正常完成。压缩 RPC 诊断保留脱敏后的失败原因，不保存重复正文。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-13 — 正确识别 Pi 模型请求失败

- 类型：修复、测试
- 用户可见行为：Pi 请求超时、重试耗尽或中止时直接报告执行失败，不再在产物校验阶段误报 required_artifact_missing 或声称角色已经完成工作。Pi 内部重试成功后继续正常收集成果。
- 实现范围：新增 PiRpcOutcome 跟踪最终 assistant stopReason 和 auto_retry_end，Adapter 在 agent_settled 后、读取结果前检查失败状态；压缩事件保留 stopReason/errorMessage，并按实际凭据值脱敏。只有后续成功 assistant 消息能清除失败，避免 Pi 将中止视作重试成功时误收旧结果。增加 Adapter 失败、中止、重试恢复与日志诊断回归测试。
- 状态与兼容性：版本从 0.1.3 升至 0.1.4；无 Schema、Git 事件或数据迁移。既有失败 Attempt、保留工作树和历史诊断不改写。
- 验证：读取用户保留的两次 Pi 会话及 RPC 日志，均为 `Request timed out.`、3 次重试耗尽、正文为空后收到 `agent_settled`，复现误判链路。Electron Node `24.18.0` 下 Adapter/事件压缩/真实 Pi RPC 共 `14` 项通过，`1` 项既有 stderr 夹具断言失败（与 `0.1.3` 一致）；新增失败归因、中止、重试恢复和诊断脱敏 `5` 项全部通过。全量 lint、typecheck、核心与桌面构建及变更文件格式检查通过；未重复运行全仓测试。
- 已知限制：本修复纠正失败归因，不修复外部模型服务的请求超时；仍需重试或排查服务连接。继承 0.1.3 的 PATH Node 启动器要求、开发 Node >=22.22 要求、既有 stderr 测试失败和 macOS 安装验证限制。上述既有 stderr 测试在最后一轮还出现 Windows 清理临时目录 EBUSY；新增测试和真实 Pi 集成测试通过。
