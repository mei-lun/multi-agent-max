## 当前功能基线

继承 0.1.28 的 Provider 地址归一化、Responses 流式传输、Review 格式中立归一化、无模型 Local Execution Draft 恢复，以及自动 Review Decision 聚合与 merge readiness 推进。

- 只有 Workflow 中显式 `review_gate` 生成的 Review Task 可以审核其绑定的上游 Attempt、Artifact 和 commit；普通 `role_task` 不会隐式创建 Review。
- `maxRevisionAttempts` 表示初次正式交付之后允许的自动返工次数；初次交付本身不消耗返工额度。
- Review 节点与 `changes_requested` 回退边使用同一返工次数口径，并取两者中更严格的限制。
- 返工额度尚未耗尽时，`changes_requested` 自动创建新 Attempt 并继续 Review；额度耗尽后才进入 `blocked`。

## 本版本变更记录

### 2026-09-20 - 修复自动 Review 返工次数提前耗尽

- 类型：修复、测试。
- 用户可见行为：`maxRevisionAttempts = 2` 现在允许初次交付之后自动执行两次正式返工；不会在第一次返工仍被要求修改时提前进入 `blocked`。
- 实现范围：Review 聚合计算直接使用 `formalRevisionNumber` 作为已消耗返工数；有效上限统一按 Review 节点和回退边的返工次数取最小值；定向测试覆盖可用额度、额度耗尽和回退边限制。
- 状态与兼容性：版本从 0.1.28 升至 0.1.29；不修改 Workflow、Review、Attempt、Artifact 或 Git 事件 Schema，无迁移要求。既有 Run Bundle 保持原配置，新产生的聚合使用修正后的计数语义。
- 验证：定向测试先在旧实现上稳定复现 3 项失败；修复后 Review 计数、聚合、正式 revision lineage、Review Aggregate、Human Review Kernel、分歧裁决和 publisher 共 8 个文件、26 项测试通过，相关恢复与自动 Review 测试此前共 12 项通过，`changes_requested` 与 `approved` 真实 Git 恢复案例分别通过。Node 24.19.0 下全仓 TypeScript 检查通过，改动文件 oxlint、oxfmt 和 `git diff --check` 通过。现有阻塞 Run 已通过正式 Restart Application API 创建自动执行的替代 Run `run.d291887aad7746ae8767c5766825e282`；该 Run 正常启动 Pi 并持续生成执行事件。
- 已知限制：达到真实返工上限后仍按有界工作流规则进入 `blocked`；本修复不会让普通任务参与审核，也不会绕过显式 Review Gate。替代 Run 的初始设计 Attempt 持续执行约 7 分钟后遇到 `executor_timeout`，同一 Attempt、Draft、worktree 和 Pi session 已保留为 `waiting_for_resume`；当前自动协作规划器把带中断信息的 running Attempt 视为仍在工作，不会自动触发本地续跑，这属于独立的超时恢复缺口。
