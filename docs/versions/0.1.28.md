## 当前功能基线

继承 0.1.27 的 Provider 地址归一化、Responses 流式传输、Review 格式中立归一化、Pi 最终响应选择和无模型 Local Execution Draft 恢复。

- 自动 Review Attempt 在同一原子交付中记录 Attempt Result、Artifact 和 Review Decision。
- Review Decision 达到节点最小提交数后立即发布确定性聚合；`changes_requested` 沿 Workflow 的有界回退路径继续返工，`approved` 继续检查 merge readiness。
- Review 聚合发布保持幂等；已有同一 Review 节点和不可变 subject 的聚合不会重复创建。
- 非 Review 的显式 `json-schema` Artifact 继续严格校验，不恢复终端尾部、进程退出、自然语言自称完成或 idle 即完成语义。

## 本版本变更记录

### 2026-09-20 - 修复自动 Review 已提交但工作流不继续推进

- 类型：修复、测试。
- 用户可见行为：自动 Review（包括从保留 Pi 最终响应恢复的 Review）提交后会立即聚合；`changes_requested` 不再停留在已提交但未聚合状态，而是按 Workflow 定义继续进入返工。
- 实现范围：Attempt 后台 runner 在原子交付 Review Decision 后调用既有 Review 聚合和 merge readiness 发布器，并将后交付推进失败隔离为诊断事件；真实 Git 恢复测试覆盖 `changes_requested` 聚合、`approved` merge readiness 及源 Task 状态推进。
- 状态与兼容性：版本从 0.1.27 升至 0.1.28；不修改 Workflow、Review、Attempt、Artifact、Local Execution Draft 或 Git 事件 Schema，无迁移要求。
- 验证：Node 24.19.0 下初始定向真实 Git `changes_requested` 恢复测试通过，相关 runner、自动 Review 和恢复测试共 13 项通过；最终改动文件的 oxlint、原生 esbuild 编译与 `git diff --check` 通过。当前 Run 已用同一聚合发布器补发，源 Task 从 `in_review` 进入 `changes_requested`；随后 `0.1.28` 桌面实例自动完成返工和下一轮 Review，并立即生成新的 `review_aggregation_recorded`。该 Review 再次要求修改后，既有最大返工次数规则将聚合结果确定性升级为 `blocked`，流程未再次停滞。回归测试现同时覆盖 `changes_requested` 和 `approved`/queued merge entry，但最终双案例重跑未能在当前主机启动 Vitest worker。
- 已知限制：本修复不改变 Review quorum、分歧处理或最大返工次数规则。全仓 TypeScript 检查在当前 Windows 主机虚拟内存余量不足时于约 845 MB 提交内存处终止，最终 Vitest/oxfmt 重跑也因同一系统提交内存不足未启动；既有 `review-aggregation-publisher.test.ts` fixture 缺少 `definition.edges`，仍会在 revision-limit 路径失败。
