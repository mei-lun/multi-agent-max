## 当前功能基线

本版本继承 `0.1.1` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-04 - 增加 Codex 资源选择导入与健康检查

- 类型：功能、优化、配置、测试、文档
- 用户可见行为：Resources 页面可从本地 Codex 的用户、内置、已启用插件和 `config.toml` 来源搜索并选择导入 Skill 与 MCP；内容更新后直接激活最新版。用户可一键检查全部当前 Skill、MCP 和知识库，并查看“未检查”“正常”“异常”或“Pi 不兼容”标记和脱敏原因。
- 实现范围：新增共享导入/健康契约、Codex Home 与插件发现、结构化 TOML 解析、事务导入、MCP 加密凭据包解析、Pi Skill loader/MCP capability/Knowledge connector 健康探测、可信 IPC、Resources 导入 Dialog、健康 Badge 与双语文档；相关代码位于 `src/shared/mam`、`src/main/mam/resources`、`src/main/mam/gateways`、`src/main/ipc` 和 `src/renderer/src/features/mam`。
- 状态与兼容性：版本从 `0.1.1` 升至 `0.1.2`。新增本机 `resource-health.json` 和 `resource-import-transaction.json` 派生/恢复文件；不改变 Scheduler Git 事件、Run、Role、Workflow 或 Attempt Schema。旧本机 MCP 连接继续可解析；已冻结 Run/Attempt 保留旧 Profile 版本，新 Run 只使用当前激活版本。
- 验证：Node 24.19.0 下，资源专项测试 `10` 个文件、`25` 项通过、`1` 项 Windows symlink 条件跳过；`corepack pnpm lint`、`corepack pnpm typecheck`、`corepack pnpm build` 和 `corepack pnpm smoke:desktop:seeded` 通过。seeded smoke 实际调用 Codex discovery IPC 并确认候选载荷不含环境变量、请求头或密钥值字段。完整测试为 `124` 个文件、`382` 项通过、`1` 项跳过、`6` 项失败；其中 Windows 文件权限和 Git 集成的 `5` 项与改动前基线相同，Pi adapter 的 stderr 夹具断言在 Node 24 下失败，资源相关测试全部通过。独立代码审查提出的插件 MCP manifest、bearer/SSE 映射、凭据精确更新、解密失败隔离、ID 碰撞和 UI 错误可见性问题均已修复并回归验证。
- 已知限制：不从 Codex 导入知识库；`vector-store` 和 `mcp-resource` 当前标为 Pi 不兼容。健康检查不调用模型或 MCP 工具，因此不保证模型在具体任务中主动选择资源。macOS 真实安装环境仍需发布门禁验证。仓库全量 `format:check` 在改动前后都会报告既有文件格式差异，本次仅对变更文件执行精确格式检查。
