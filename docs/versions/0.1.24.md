## 当前功能基线

继承 0.1.23 的 Provider 地址归一化、模型目录发现、协议分流、Review 工作流和 Design Assistant 诊断。

- OpenAI Responses/Compatible 模型支持可配置的推理强度；Responses 请求默认使用 `medium`，并通过 `reasoning.effort` 发送。
- Design Assistant 的 Responses 请求使用流式传输并解析 Responses SSE 增量。
- Pi RPC 的 Responses 自定义模型声明 reasoning 能力，并把 Role/Model 的推理强度映射为 Pi thinking level。

## 本版本变更记录

### 2026-09-20 - 对齐 Responses 流式与推理强度契约

- 类型：修复、功能、测试、配置。
- 用户可见行为：MAM 不再以同步、无推理强度的 Responses 请求调用模型；请求包含 `stream: true` 和 `reasoning: { effort: ... }`，默认/可选档位包含 Medium。Pi RPC 和 Design Assistant 均沿用该配置。
- 实现范围：Design Model request/gateway SSE 读取、Model Profile 推理强度字段、Pi models.json reasoning 元数据和启动参数映射、契约测试。
- 状态与兼容性：版本从 0.1.23 升至 0.1.24；Profile Schema 无变化，`defaultInference` 原有扩展字段承载 `reasoningEffort`，无迁移要求。历史 OpenAI Responses Profile 在运行时默认 Medium。
- 验证：本地 Responses SSE/JSON 契约测试、Provider/Design/Pi 定向测试、TypeScript 类型检查、lint 和格式检查。
- 已知限制：实际中转仍需接受 OpenAI Responses 的 `reasoning.effort` 和 SSE；不支持的档位由中转返回错误时不会隐式切换协议。
