## 当前功能基线

本版本继承 `0.1.2` 的所有仍受支持能力，包括 Git 驱动的 Workflow Run 状态、固定角色工作流、独立 Attempt worktree、审核与合并队列、设计助手、执行观测、纯本地或分布式 Git 协作以及本机 Profile 和资源绑定。

- Git 状态继续由 `mam-state` 分支持久化；Scheduler Kernel 独占权威状态和受控 Git 操作。
- 每个可执行节点固定一个 Role Profile；Role 显式绑定 Skill、MCP 和知识库，不继承全局 Executor 资源。
- 当前生产 Attempt 继续只使用 Pi RPC；Codex CLI 与 Grok CLI Adapter 尚未启用。
- Pi 隔离启动器使用应用主进程的运行时执行 Pi，与 JavaScript Executor 预检查一致；Electron 使用 `ELECTRON_RUN_AS_NODE=1`。RPC 客户端仍通过 PATH 中的 Node 启动轻量启动器，但不会使用该 Node 加载 Pi 依赖。
- Resources 支持从本地 Codex 用户、内置、已启用插件和 `config.toml` 来源选择导入 Skill 与 MCP，更新后激活最新版；当前 Skill、MCP 和知识库支持健康检查与脱敏诊断。
- 角色本机绑定、密钥、资源健康结果和导入事务状态只保存在本机，不写入 Git 状态；已冻结 Run/Attempt 保留原 Profile 版本。
- macOS 仍是发布门禁；Windows 支持开发验证，Linux 尚未纳入发布范围。

## 本版本变更记录

### 2026-09-13 — 修复 Pi 执行误用 PATH 中的旧 Node

- 类型：修复、测试
- 用户可见行为：桌面应用启动 Pi 时使用自身运行时，避免系统 Node 20 加载 `undici@8.5.0` 时因缺少 `markAsUncloneable` 报 `executor_process_failed`。
- 实现范围：`pi-rpc-invocation.ts` 显式传递主进程运行时路径；`pi-isolated-launcher-source.ts` 使用指定路径启动 Pi，缺失或不可用时明确失败，不切换运行时。启动器控制字段不传入 Pi 子进程。增加真实进程运行时选择测试及 Adapter 环境断言；真实 Pi RPC 测试清理目录增加有限重试，覆盖 Windows 在进程退出后短暂保留工作目录句柄的情况。
- 状态与兼容性：版本从 `0.1.2` 升至 `0.1.3`；无 Git 事件、Schema 或用户数据迁移。历史失败 Attempt 和保留工作树不变，新执行生成更新后的启动器。
- 验证：在 Windows 上用 PATH Node `20.19.6` 直接启动 Pi 复现原始 `markAsUncloneable` 异常；使用 Electron `43.2.0` 的 Node `24.18.0` 运行验证且保留旧 PATH Node，新增启动回归 `4` 项、真实 Pi RPC 本地 Provider/Application API 集成 `1` 项全部通过。全量 lint、typecheck、核心与桌面构建通过，变更文件格式检查通过；独立代码审查未发现回归。Adapter 测试 `5` 项通过、`1` 项因既有 stderr 夹具断言失败，与 `0.1.2` 档案记录一致。本次未重复运行全仓测试。
- 已知限制：官方 RPC 客户端仍要求 PATH 中存在能够执行轻量 `.mjs` 启动器的 Node；本修复不改变开发环境 `Node >=22.22` 要求。既有 Adapter stderr 夹具问题未在本次修改。不从 Codex 导入知识库，`vector-store` 和 `mcp-resource` 仍标为 Pi 不兼容；健康检查不保证模型实际选择资源。macOS 打包安装环境仍需发布门禁验证。
