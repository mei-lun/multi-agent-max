## 当前功能基线

继承 0.1.19 的 Claim、Local Execution Draft、Formal Delivery、多角色 Review Aggregate、恢复和权威校验基线，并修复桌面自动协作与本地 Draft 状态脱节的问题。

- 普通 Role Task 和 Review Task 在成功校验前只保留本地 Draft；正式交付才原子创建共享 Attempt、更新唯一当前交付并完成 Claim。
- 自动协作将 active Task Claim 视为执行中，不依赖交付前共享 Attempt，也不会对同一 Task 重复发送启动请求。
- 同一应用进程中的重复启动仍合并为一次执行；重复调用在首次启动完成后读取当前快照，不复用启动瞬间的旧快照。
- 实时观测可在正式 Attempt 尚未创建时通过诊断事件的 Task identity 关联节点、Role 和活动 Claim，并显示运行中状态与实时事件。
- `needs_attention` Draft 不进入自动恢复集合；只有用户从 Task 操作入口显式继续时才可恢复同一 Attempt。
- Local Draft 持久化不含密钥值的冻结执行上下文；重启恢复复用原 Executor Profile、本地 Executor Binding、Effective Config 与已物化资源，并校验 snapshot/hash 一致性。
- Draft 累计 active runtime；Codex、Grok 与 Pi 都消费剩余活动预算，恢复不会重置 provider request 或进程 timeout。
- Reviewer Formal Delivery 原子携带 Review Decision，并校验 Review Gate、Reviewer Task、Attempt、Role Instance 与不可变 Subject 绑定。
- Delivery lineage 覆盖普通 DAG、穿过系统节点的上游 Task、动态 Task 依赖和 Reviewer Subject；缺失、重复或过期 lineage 均被权威端拒绝。
- Review Aggregate 使用 Workflow 固定顺序的 quorum 成员集合，并在 CAS 重试时重校验当前 Subject、成员集合和聚合结果。
- 同机继续必须显式确认未知副作用；强制接管的新 Claim 不能复活旧 generation Draft；当前交付和 legacy 唯一交付均通过统一 resolver 解析。

## 本版本变更记录

### 2026-09-17 - 修复本地 Draft 重复启动与实时观测延迟

- 类型：修复、测试、文档。
- 用户可见行为：自动协作运行期间不再高频重复启动同一 Task，不再在交付完成时出现 `task_not_startable:in_review` 或 `task_not_startable:submitted`；实时观测在本地 Draft 执行期间持续显示 Role 消息、工具和状态，不再等到任务完成后一次性出现。
- 实现范围：桌面自动协作 action 规划、实时观测节点 view model、本地 Task 执行注册表、Attempt 启动服务及对应回归测试。
- 状态与兼容性：版本从 0.1.19 升至 0.1.20；不新增 Git 事件、本地持久化字段或 Schema，不需要数据迁移。Formal Delivery 权威边界保持不变。
- 验证：自动协作、实时观测、事件投影 5 个文件共 18 项通过；Attempt 执行服务 10 个真实 Git 场景通过；TypeScript 类型检查、lint、主进程/preload/renderer 生产构建和 `git diff --check` 通过。Node 20 下全量 Vitest 共 155 个文件，147 个通过，459 项通过、1 项跳过、7 项失败，另有 3 个 suite 加载失败；本次改动涉及的 timeout 用例单独复跑通过。
- 已知限制：当前 Windows 环境使用 Node 20，低于项目要求的 Node 22；全量失败包含 undici 的 Node 版本不兼容、2 项 POSIX `0o600` 权限断言、3 项既有真实 Git merge fixture 断言，以及并行负载下 1 项真实 Git timeout。全仓 `format:check` 仍报告实施前已有的 400 个文件格式偏差。跨机器仍不能恢复另一机器私有的 Pi session 或 Local Draft；macOS 发布门禁尚待执行。
