## 当前功能基线

继承 0.1.17 的功能基线，并完成 Claim、Local Execution Draft、Formal Delivery 与多角色 Review Aggregate 的一致性收口。

- Task Claim generation 在释放、重新领取和强制接管之间保持单调递增，旧 generation 被 fencing。
- Formal Delivery 在权威状态提交成功前保留 worktree；失败可继续恢复，不会先删除本地工作区。
- Delivery 记录并重校验上游正式交付 lineage；上游新 revision 后，旧下游 Draft 返回 `stale_input_lineage`。
- 应用重启后使用稳定 claimant identity，从本地 Draft manifest 恢复预分配 Attempt、worktree、Pi session、冻结配置标识和 revision lineage。
- Reviewer Formal Delivery 与 Review Decision 在一个 `task_delivery_recorded` 批次中发布；生产者新 revision 会取消旧 Subject 的未完成 Review Task 并清除其 Claim。
- `review_aggregate` 按当前 Review Subject 聚合，正确支持少于成员总数的 quorum；历史 Subject 不阻断新 revision。
- 缺少唯一当前交付的 legacy Task fail closed，不再仅凭 `submitted` 状态推进。
- 普通 Provider timeout 进入 `waiting_for_resume`；其他无法确认副作用的执行错误进入本地 `needs_attention`。

## 本版本变更记录

### 2026-09-17 - 完成协议一致性与并发安全收口

- 类型：修复、重构、测试、文档
- 用户可见行为：强制接管、重启恢复、多角色审核、上游返工和交付失败现在都遵循同一套 Claim fencing 与唯一交付规则；失败不会删除可恢复工作区，旧数据不会被下游误用。
- 实现范围：Claim generation、Draft restart restore、Delivery worktree 生命周期、input lineage、Reviewer 原子交付、Review Claim 失效、Aggregate quorum/Subject、legacy fail-closed、错误分类以及相关回归测试。
